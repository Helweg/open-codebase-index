# Origin-aware context packing, blinded agent follow-up

**Date:** 2026-09-24. **Conclusion:** This small exploratory comparison did **not demonstrate an answer-quality gain** from origin-aware packing. In the completed, harness-repaired third attempt, the two paired final scores were tied (6/12 versus 6/12) and worse for the origin-aware version (4/12 versus 10/12). The latter version cited a nonexistent source file and failed the prespecified citation verifier. Two tasks from two related Fastify integration pairs cannot support a general superiority or regression estimate.

## Attempts and blind scoring

1. The first attempt was interrupted by a 600-second supervising-tool timeout before an aggregate result. Its partial artifacts were excluded.
2. A separately approved OS-detached second attempt used the frozen task inputs and completed three answers. Its fourth arm ran a model session but emitted no answer. A read-only audit found a preexisting exclusive-write observation file from attempt one under a shared filename. This is high-confidence evidence of a scratch adapter `EEXIST` collision, although the adapter suppressed the actual exception. Two blind graders scored the three available answers before unblinding: JWT parent 6/12 (unsupported categorical `Bearer abc` outcome cap) versus candidate 12/12; rate-limit candidate 12/12, parent unscorable. **A missing parent answer is not a factual-quality zero and the apparent gain is not a complete two-pair result.** Both JWT answers received 4/4 on the cross-origin subscore.
3. A third, separately approved **harness-repair retry** changed only the scratch adapter's observation output to an owner-only, attempt-scoped directory, retaining exclusive writes. An independent reviewer approved the diff and six adapter tests passed. The same frozen prompts, seed, repository pins, plugin bundles, model, first-call budget and limits were used, with a fresh artifact directory. All four model sessions and terminal answers completed. An independent blinder copied exact terminal text into neutral private files. Two new blind graders checked the frozen rubric and pinned source before unblinding; separate adjudication resolved the categorical-outcome cap. Both graders then independently confirmed the fabricated-citation cap for the rate-limit candidate.

Both JWT answers had correct cross-origin branch descriptions (4/4 descriptive subscore), but each categorically asserted that literal `Bearer abc` must produce HTTP 401. The pinned source establishes extraction, not token validity or the resulting HTTP status; the frozen rubric caps an unsupported categorical conditional outcome at 6. In the rate-limit pair, the candidate's otherwise substantial answer cited `fastify/lib/initial-config.js`, which does not exist in the pinned Fastify tree. Both graders independently applied the rubric's fabricated-source citation cap of 4, and the preregistered file-existence verifier independently failed this arm for that nonexistent `CITED_PATH`. Its agent exited successfully and did produce an answer; its trial success flag is false because of the verifier, not an infrastructure failure. The parent scored 10/12. Cross-origin descriptive subscores were 2/4 parent and 4/4 candidate, but additional origin coverage did not prevent the citation error.

In the third attempt the four arms each called `codebase_context` once with first budget 300. Parent/candidate model-reported costs were about $0.01108/$0.01356 for JWT and $0.01555/$0.01495 for rate-limit, excluding indexing. Agent durations were about 79/113 seconds for JWT and 80/194 seconds for rate-limit. These tiny, variable measurements are **not** evidence of a general speed or cost difference. Index preparation and earlier attempts add real overhead. The hard per-arm deadline was eight minutes; monetary, tool-call and token limits were polling safeguards rather than hard caps.

**Interpretation:** The two complete third-attempt pairs favor neither the candidate nor a causal explanation of the isolated second-attempt JWT improvement. Repeating the same frozen tasks after unblinding the earlier attempt is a disclosed harness-repair retry, **not an independent unseen cohort**. The sample is too small and related to estimate efficacy, while fixed probes already showed both origins under both versions. The clear actionable failures are unsupported conditional-runtime claims and nonexistent-file citations. Do not publish an accuracy, speed or cost superiority claim. Future work needs source-validating citations, evidence-displacement checks, privacy-safe bounded retrieval traces and a larger newly frozen multi-family cohort with a real default-budget sensitivity arm. Private prompts, audits, rubric and mapping remain outside the repository.
