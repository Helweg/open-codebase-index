# Origin-aware context packing, blinded agent follow-up

**Date:** 2026-09-24. **Conclusion:** The new evidence packer has **not demonstrated a reliable answer-quality gain**. One complete paired answer favored the new version, 12/12 versus 6/12. The other pair cannot be scored for comparative answer quality because the parent arm completed a model session but its adapter failed before emitting the answer. This is a two-task exploratory study, not a general efficacy estimate.

## Frozen comparison

The control was the OCBI plugin at `385b1a9c5e8a90ccfa8aad3af5b378ed8e6ba010`, not a no-plugin control. The treatment was `ef2e5f8f46f051127340be23004d63e2830caa87`, differing in origin-aware conceptual evidence selection and source labels. Built plugin SHA-256 values were `946ece4e956c10dd75ebdb7bcb99df1cee1b038c9cc3493618d711a79b107e81` and `118f8be81e5d1cce42b54cae9ecb745cbb94a979c1fdbeb3053bb95961129e7d`. Both loaded the same native binding and exposed identical inventories of 34 IDs, 33 model-visible tools, and 20 OCBI tools. Both used the default OpenCode `build` agent, Go DeepSeek V4.1 Flash, isolated private workspaces, the same frozen prompt, index preparation, verifier, and limits. An identical, preregistered suffix asked for `tokenBudget=300` on the first `codebase_context` call if used. This measures an *encouraged tight-budget workflow*, not unprompted default use. All four arms actually made one 300-token context call.

Two source-backed, read-only questions covered fastify-jwt `0fa894171e3af59f26b96cac45ed8ab8c2cfc276` with fastify-cookie `104aca792e25b3791782c4eabfde8d7fd6c89063`, and fastify-rate-limit `78a7d41143f5418fef3cfe3ac6b46c944e637dc2` with Fastify v5.9.0 `2e45a4472fc83d1342661f4ec8a92334f46277c9`. These are pinned, clean, semver-compatible source fixtures with direct integration tests, not cryptographic proof of a published dependency installation. Independent review approved the prompts and separate private rubric before inference. Frozen manifest SHA-256: `4316e1f9b7cbbbf8a18b08ac12d9c5181c44783ace7e49b65e47ae7b1e41899f`; rubric: `1122fb714be383b3bcfb04b2554cf2d7c705253aca0c9dc2e267aba37699516f`; fixed probes: `9ae0b405df9140b8c26d5e06ac21921c7061548147e780f8592399d321c52253`. The rubric and answer mapping were not exposed to the solvers or graders, respectively.

Pre-inference fixed source queries, repeated without retuning at 300 and 1200 tokens, returned both source origins in **both** plugin revisions for **both** tasks. Thus these probes did not establish a new origin-coverage gain. The treatment added explicit origin labels. In the rate-limit 300-token probe it selected two locations where the parent selected three, a possible cost of labeling or evidence displacement. No answer-quality conclusion follows from the probe alone.

## Execution and blind scoring

The first attempt was interrupted at 600 seconds by its supervising tool, before an aggregate result. Its partial artifacts were excluded. After recording this deviation and confirming that the owned processes had stopped, a separately approved, OS-detached supervisor ran the **unchanged** frozen tasks, seed, model, plugin builds, and budgets in a new artifact directory. That second attempt completed with an aggregate result. One parent arm produced no terminal answer due to an adapter failure. Three nontruncated terminal answers were copied byte-for-byte to neutral, owner-only files by an independent blinder. Two independent graders applied the frozen 12-point rubric against pinned source before the mapping was opened. They agreed on the final scores and the relevant unsupported-assertion cap.

| Task | Parent | Origin-aware version | Comparable answer delta |
| --- | ---: | ---: | ---: |
| JWT and cookie verification | 6/12, capped from 10/12 for an unsupported categorical claim about `Bearer abc` | 12/12 | +6 on **one** complete pair |
| Proxy-aware rate limiting | No emitted answer, unscorable for factual quality | 12/12 | Not estimable |

The JWT answers both received 4/4 on the rubric's cross-origin subscore. The complete pair therefore shows an answer difference, but does not identify an origin-coverage mechanism. Its model-reported costs were about $0.01129 parent and $0.01304 treatment. The rate-limit treatment reported about $0.01549. The failed parent session incurred model work, but its cost amount was not emitted. These exclude indexing and are not stable cost estimates. All four arms made one context call with the requested 300-token first budget.

A read-only failure audit found that the missing-answer parent arm had completed a model session and written numeric observation metadata (`modelCalls=1`, `contextCallCount=1`, `firstContextCallBudget=300`). It then failed downstream before emitting stdout telemetry. Its audit stderr was only `Serve adapter failed (details withheld)`. The exact exception and the answer are unavailable, so this failure **must not** be presented as a model answer-quality loss or attributed to the parent plugin. The answer-presence workflow succeeded in three of four arms, and the factual-quality comparison has only one usable pair. A two-sided sign test on that one pair supplies no meaningful superiority evidence.

**Next step:** Fix adapter output-emission diagnostics and retain bounded, privacy-safe evidence about retrieval contents and displacement. Then run a larger, newly frozen, multi-family paired cohort. Do not claim general accuracy, speed, or cost superiority from this study. Private audits, rubric, and mapping remain outside the repository.
