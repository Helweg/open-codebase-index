# Exploratory v0.32.2 cross-repository comprehension study, 2026-09-24

**Result: no causal OCBI gain established.** Four preregistered paired tasks compared OpenCode 1.18.32's default `build` agent and `opencode-go/deepseek-v4.1-flash` with the same agent plus a locally built OCBI v0.32.2 release candidate. One VS Code/ripgrep task favored treatment on blind accuracy, one was essentially tied, and both Next.js/Chakra tasks produced no answer in either arm. Crucially, **neither completed treatment task invoked an OCBI tool**. The observed score difference cannot be attributed to retrieval.

Two graders, blind to arm mapping, checked source citations against the frozen rubric. An independent blind adjudicator confirmed the task-01 control answer's categorical, unsupported assertion that the pinned npm artifacts came from the inspected ripgrep fork's own pipeline. The rubric's invented-lineage cap yields 5/12 despite otherwise substantial source coverage. The two graders differ by at most one point on the remaining answers. Missing Next.js/Chakra answers score zero by the preregistered rule. All four Next arms exited after roughly 305–311 seconds with a generic adapter failure and no retained final text; this symmetric ~300-second failure is consistent with an HTTP-client deadline but its precise cause was not captured. Do not score the runner's clean-Git/presence verifier as factual accuracy: it rejected one VS Code/ripgrep control answer for citing a nonexistent path even though graders could score its remaining content.

At the preregistered >=9/12, no-critical-cap threshold, control succeeded on one of four tasks and treatment on two of four. There was **one treatment-only discordant success**, no control-only success, and an exact two-sided paired sign-test **p = 1**. Two tasks are correlated within each repository pair. Even four discordant wins in four pairs would have p = 0.125, so this small cohort cannot establish superiority. For completed VS Code/ripgrep tasks, treatment took about 197/230 seconds versus control 126/113 seconds and reported costs about $0.0342/$0.0322 versus $0.0291/$0.0282. Index preparation added roughly 155–321 seconds per treatment trial. These are observations, not stable latency or cost estimates.

## What the failure taught us

The candidate exposed working indexed retrieval but the OpenCode agent chose built-in `bash`, `read`, `glob`, and `grep` instead. Read-only diagnosis found that every frozen explanatory task was classified as an *external lookup* because incidental words such as `npm`, `package`, `crate`, or `framework` triggered the external-first heuristic. After removing those false positives, incidental file paths and build/test terms still suppressed conceptual routing. Commit `b2674f1` on local main and cherry-pick `07fe75c` on the separate release candidate correct this **eligibility** defect with generic source-grounded tests and explicit external/direct-path negatives. That later fix was **not** present in the graded candidate and cannot retroactively change these outcomes. A subsequent real OpenCode request capture must verify the hint actually reaches the main agent. Tool eligibility or use alone still cannot establish answer-quality benefit; repeat independently frozen, blinded paired tasks and address the adapter's symmetric timeout before claiming one.

No release was pushed, tagged or published by this study. Protected transcripts, source paths and grader mapping remain in owner-only local artifacts, not in this report.
