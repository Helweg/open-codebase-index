# Domain docs

This is a single-context repo. Before exploring, read the root `GLOSSARY.md` and relevant decisions in `docs/adr/`, if present.

Use glossary terms in specs, issues, tests, and refactor proposals. Flag any proposal that contradicts an ADR; name the decision and why it merits revisiting.

Proceed silently when these files do not exist. Use `/domain-modeling` to create them only when a term or decision is settled.
